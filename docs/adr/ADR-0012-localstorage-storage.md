# ADR-0012：训练记录存 localStorage——无后端、无账号

- 状态：已采纳（2026-11-09，用户确认）
- 相关：ADR-0010（换血总纲）、ADR-0011（无构建纯静态）、ADR-0013（模块规格）

## 背景

训练应用唯一的持久化需求是训练记录（成绩、历史、统计）。三个模块都是纯客户端实时交互，服务端在数据路径上没有天然角色。用户确认：纯前端静态站，只自己用，零登录。

## 决策

### 存储真源

**localStorage 是训练记录的唯一真源。** 无 D1、无 KV、无任何服务端存储。

### 数据模型

追加式会话日志（append-only session log），单 key 存 JSON 数组，按 `ts` 升序：

```
key: mindgym:v1:sessions
entry: {
  id:        string,   // crypto.randomUUID()
  module:    'math' | 'nback' | 'meditation',
  ts:        number,   // 会话开始时间戳（ms）
  params:    object,   // 该次训练的输入参数（见 ADR-0013）
  result:    object    // 该次训练的产出成绩（见 ADR-0013）
}
```

规则：

- **写入时机唯一**：一次会话正常结束（或明确放弃）时一次性 `push` + 写回。中途刷新/关页不留痕，不算一次训练。
- **派生数据不落盘**：连续天数、总次数、趋势曲线全部从日志现算，不做缓存副本。日志就是唯一事实，统计是它的纯函数。
- **schema 演进靠版本号**：key 中的 `v1` 是数据版本。未来字段变更时新开 `v2` key 并写迁移函数，禁止原地改语义。

### 备份纪律

localStorage 会被「清除站点数据」一键抹掉，且不随设备迁移。**stats 页必须提供导出**：把日志下载为 JSON 文件，这是唯一备份手段。MVP 只做导出不做导入（导入属恢复场景，出现真实需求再开 ADR）。README 明示备份纪律。

### 多设备

不同步，各自记录各自的。接受此限制；若未来需要跨设备，方案是加后端（新 ADR），不是在 localStorage 里 hack。

## 后果

- 换浏览器/清缓存 = 记录全丢。导出按钮的存在感要在 stats 页足够高。
- 日志数组随年份增长，单 key 体积变大。每会话约 150 字节，一天十条一年不到 1MB，远低于 localStorage 5MB 上限；无需分片，但 stats 现算函数要注意只在必要时全量扫描。
- 「D1 唯一真源」「大内容写入必须走参数绑定」等旧规则随 D1 拆除一并作废。
