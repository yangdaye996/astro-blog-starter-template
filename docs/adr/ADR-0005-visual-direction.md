# ADR-0005：视觉基调——少数派式清爽卡片，且不做暗色模式

- 状态：已采纳（2026-11-08）
- 相关：ADR-0003（字体分工）、ADR-0001（无 SSR，切换状态无法服务端记忆）

## 背景

原始需求是"国产、中文、现代化风格"。这三个词都无法直接指导实现："国产"不是一个视觉风格，"现代化"可以指向 SaaS 暗色渐变，也可以指向杂志式衬线排版。必须钉死到可执行的设计语言，否则实现只能靠猜。

模板现有样式基于 Bear Blog 的默认 CSS（`src/styles/global.css` 顶部注释有出处），主色 `#2337ff`，字体 Atkinson Hyperlegible，带灰色渐变背景与较重的多层阴影——是典型的英文极简博客观感。

## 决策

### 设计语言

采用**少数派式清爽卡片**：

- 蓝灰主色，克制、偏工程感，不用高饱和撞色。
- 信息密度偏高：卡片上同时呈现标题、描述、日期、分类/标签徽标、字数与阅读时长，而非只放一个标题。
- 清晰层级：标题层用思源黑体 Bold 子集（ADR-0003），正文层用系统字体栈，元信息用更小字号 + 降低对比度的灰色。
- 卡片用细边框 + 轻阴影 + 小圆角，不用大面积渐变与光晕。
- 细线分隔与充足留白撑起"清爽"，而不是靠装饰元素。

### 首页形态

**单栅卡片流**：文章卡片单列铺满内容区，最新在上。不做双栏侧边栏，不做顶部 hero 大图。

理由：侧边栏在移动端必须折叠，等于要维护两套布局；hero 区会把内容挤到首屏之外。单栅卡片流最接近少数派首页，且实现与响应式成本最低。

### 明确不做暗色模式

只做浅色。不写 `prefers-color-scheme` 媒体查询，不提供切换按钮，不注入防闪烁的内联脚本。

## 理由

- 不做暗色是需求方明确选择。它带来一项实质性简化：**整套设计令牌只需一组值**。若做暗色，每个颜色变量都要双份，且纯静态站为防止首屏闪烁必须在 `<head>` 注入一段读取 `localStorage` 的内联脚本，这段脚本无法被缓存、会阻塞渲染，与"清爽"的性能目标相悖。
- 单栅卡片流让"信息密度高"这个少数派特征得以体现——双栏会把卡片压窄，密排元信息就放不下。
- 蓝灰而非高饱和色，是因为技术博客的正文里已经有代码块高亮的多种颜色，主色再抢就会杂乱。

## 代价

- 夜间阅读体验差，且无法通过系统设置改善。这是明确的取舍。
- 未来若要补暗色模式，成本不是"加一组变量"，而是要回头给所有硬编码颜色补变量、并处理首屏闪烁脚本——属于推翻性改动，需另开 ADR。
- 单栅在宽屏（>1400px）上会显得空旷，需要靠限制内容区最大宽度解决，而不是靠填充侧边栏。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 极简文字流（无卡片） | 加载最快最耐看，但与需求方选定的"卡片"形态直接冲突。 |
| 现代 SaaS 暗色风 | 大标题 + 渐变 + 光晕容易显得模板化，且与"不做暗色"的选择矛盾。 |
| 中式杂志排版（衬线 + 竖排点缀） | 差异化最强，但与"少数派式清爽卡片"是两种语言，混用会不伦不类。 |
| 双栏 + 侧边栏 | 信息密度更高、更"国产博客"，但移动端需维护第二套折叠布局，成本翻倍。 |
| Hero 简介 + 卡片流 | 兼顾个人品牌，但会把内容推出首屏；个人介绍已由 `/about` 承载。 |
